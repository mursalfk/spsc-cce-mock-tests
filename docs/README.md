# SPSC CCE-2026 Mock Tests

Free, unofficial practice tests for the SPSC CCE-2026 screening test (Sat 28 Nov 2026). A static site on GitHub Pages: **63 full tests, 12,600 questions**, three levels of 21 tests each.

| Level  | Tests    | Ids    | What it is |
|--------|----------|--------|------------|
| Easy   | 01 to 21 | 1-21   | Pitched at the paper, a little above it in places |
| Medium | 01 to 21 | 22-42  | A clear step above the paper |
| Hard   | 01 to 21 | 51-71  | Harder than the paper, on purpose |

Every test has 200 MCQs, marked +1 right, −0.25 wrong, 0 skipped. Pass mark 66 net, 200 minutes.

## Folder layout

```
index.html  test.html  about.html  topics.html     the pages
assets/
  css/style.css                      all styling and the five themes
  js/app.js                          sign-in, Firestore history, shared helpers
  js/catalog.js                      index page (level switcher, cards, stats)
  js/runner.js                       the test runner (one page for all 63 tests)
  js/report.js                       PDF report and email
  js/topics.js                       topics page (reads data/topics.json)
  js/ui.js  js/theme.js              theme and text-size controls
  vendor/  fonts/                    third-party files, bundled so nothing loads from a CDN
  firebase-config.js                 your Firebase keys (never overwritten by updates)
data/
  questions.csv                      THE source of truth: every question, one row each
  config.json                        exam date, marking, levels, section order
  catalog.json  topics.json  tests/*.json   generated by tools/build.py, loaded by the site
tools/build.py                       validates the CSV and generates the JSON
backend/
  Code.gs                            Apps Script mailer
  firestore.rules                    Firestore security rules
docs/                                these notes
```

Nothing under `data/tests/`, `data/catalog.json` or `data/topics.json` is edited by hand. They are rebuilt from the CSV.

## How a test is opened

`test.html?t=hard-07` fetches `data/tests/hard-07.json`. The test id stored in Firestore is the level base plus the test number: Easy +0, Medium +21, Hard +50 (so Hard 07 is 57). Ids must stay in 1 to 99. The index page is driven by `data/catalog.json`, and a link such as `index.html#hard` opens a level directly.

## Adding or fixing questions

See `data/README.md`. In short: edit `data/questions.csv`, run `python tools/build.py`, commit, push.

## Local preview

```
python tools/build.py
python -m http.server 8000
```

Open http://localhost:8000. Sign-in needs your own `assets/firebase-config.js`.
